## 2. Постановка задачи и контекст

### 2.1. Предметная область и задача

**Тип задачи:** Регрессия — предсказание числового значения индекса счастья (Life Ladder) в диапазоне от 0 до 10.

**Пользовательский сценарий:** Аналитик или исследователь загружает в сервис данные о стране (ВВП на душу населения, уровень социальной поддержки, ожидаемая продолжительность здоровой жизни, свобода принятия решений, уровень щедрости, восприятие коррупции, позитивный и негативный аффект) и получает предсказанный индекс счастья. Сервис может использоваться для мониторинга качества жизни, сравнительного анализа стран и оценки эффективности социально-экономических программ.

### 2.2. Формулировка задачи в терминах ML/ИИ

**Входные данные (8 признаков):**

| Признак | Описание | Тип |
|---------|----------|-----|
| Log GDP per capita | Логарифм ВВП на душу населения | числовой |
| Social support | Уровень социальной поддержки | числовой |
| Healthy life expectancy at birth | Ожидаемая продолжительность здоровой жизни | числовой |
| Freedom to make life choices | Свобода принятия жизненных решений | числовой |
| Generosity | Уровень щедрости | числовой |
| Perceptions of corruption | Восприятие коррупции | числовой |
| Positive affect | Позитивный аффект | числовой |
| Negative affect | Негативный аффект | числовой |

**Целевая переменная:**
- `Life Ladder` (индекс счастья) — непрерывная числовая величина

**Требования к модели:**
- Скорость инференса: < 100 мс на запрос
- Интерпретируемость: возможность объяснить, какие признаки влияют на предсказание
- Точность: целевое значение MAE < 0.35

### 2.3. Целевые метрики качества

| Метрика | Описание | Обоснование |
|---------|----------|-------------|
| **MAE** (Mean Absolute Error) | Средняя абсолютная ошибка предсказания | Легко интерпретируется; показывает, насколько в среднем модель ошибается в единицах индекса (от 0 до 10) |
| **R2** (Coefficient of Determination) | Доля дисперсии, объяснённая моделью | Позволяет сравнить качество модели с простым предсказанием среднего значения |

## 4. Модели и подходы

### 4.1. Базовые (baseline) модели

В качестве baseline была выбрана **Linear Regression** с масштабированием признаков (StandardScaler). Эта модель позволила установить нижнюю границу качества для сравнения с более сложными алгоритмами.

| Модель | MAE | R2 |
|--------|-----|-----|
| Linear Regression (baseline) | 0.444 | 0.714 |

### 4.2. Линейные модели с регуляризацией

Для борьбы с потенциальным переобучением и улучшения обобщающей способности были обучены модели с L1 и L2 регуляризацией:

| Модель | Регуляризация | MAE | R2 | Улучшение vs baseline |
|--------|---------------|-----|-----|----------------------|
| Ridge (L2) | alpha=1.0 | 0.444 | 0.714 | Незначительное (менее 0.001) |
| Lasso (L1) | alpha=0.01 | 0.445 | 0.715 | Незначительное (менее 0.001) |

**Вывод:** Регуляризация не дала значительного улучшения, что объясняется отсутствием переобучения в базовой линейной модели. Это ожидаемо, так как количество признаков (8) значительно меньше размера выборки (~1900 после очистки).

### 4.3. Ансамблевые модели (без тюнинга)

Для повышения точности были обучены две ансамблевые модели с параметрами по умолчанию. Для оценки устойчивости моделей использовалась 5-fold cross-validation на обучающей выборке.

| Модель | Параметры | CV MAE (mean) | CV MAE (std) | Test MAE | R2 |
|--------|-----------|---------------|--------------|----------|-----|
| Random Forest | n_estimators=100 | 0.360 | 0.013 | 0.336 | 0.833 |
| Gradient Boosting | n_estimators=100 | 0.394 | 0.014 | 0.376 | 0.798 |

**Анализ результатов:**
- **Random Forest** показал лучший результат среди моделей без тюнинга, значительно превзойдя линейные модели (улучшение MAE на 24%).
- **Gradient Boosting** без настройки параметров уступает Random Forest как по точности, так и по устойчивости (больший CV MAE).
- Низкие значения CV MAE std (0.013-0.014) свидетельствуют о хорошей устойчивости обеих моделей.

### 4.4. Тюнинг гиперпараметров (GridSearchCV)

Для улучшения качества Gradient Boosting был проведён поиск оптимальных гиперпараметров с 5-fold cross-validation:

**Пространство поиска:**

| Параметр | Значения для перебора | Описание |
|----------|----------------------|----------|
| n_estimators | [50, 100, 150] | Количество деревьев в ансамбле |
| max_depth | [3, 5, 7] | Максимальная глубина деревьев |
| learning_rate | [0.05, 0.1, 0.2] | Скорость обучения |

**Результаты тюнинга:**

| Показатель | Значение |
|------------|----------|
| Лучшие параметры | n_estimators=100, max_depth=7, learning_rate=0.1 |
| Лучший CV MAE | 0.363 |

**Сравнение до и после тюнинга:**

| Модель | Test MAE | R2 | Улучшение |
|--------|----------|-----|-----------|
| Gradient Boosting (default) | 0.376 | 0.798 | — |
| Gradient Boosting (tuned) | 0.337 | 0.831 | **+0.039 по MAE** |

Тюнинг гиперпараметров позволил улучшить MAE на 10.4% (с 0.376 до 0.337), что подтверждает важность подбора параметров для градиентного бустинга.

### 4.5. Нейросетевые модели

В рамках данного проекта нейросетевые модели не рассматривались по следующим причинам:
1. Классические методы ансамблей показали достаточную точность (MAE = 0.337)
2. Нейросетевые модели требуют значительно больших вычислительных ресурсов
3. Для обучения нейросетей требуется больше данных для достижения сопоставимого качества

## 5. Экспериментальный протокол и результаты

### 5.1. Экспериментальный протокол

**Разделение данных:**

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Train/Test split | 80% / 20% | Стандартное соотношение для задач регрессии |
| Random state | 42 | Фиксация случайности для воспроизводимости |
| Test set | Не использовался до финальной оценки | Защита от data leakage |
| Cross-validation | 5-fold | Для оценки устойчивости моделей и выбора гиперпараметров |

**Метрики оценки:**
- **MAE** — основная метрика (легко интерпретируется)
- **R2** — дополнительная метрика (показывает долю объяснённой дисперсии)
- **Время инференса** — измерялось как среднее по 1000 запусков

### 5.2. Сравнение моделей по метрикам

| Модель | MAE | R2 | Время инференса (мс) | Комментарий |
|--------|-----|-----|---------------------|-------------|
| Linear Regression (baseline) | 0.444 | 0.714 | 8.24 | Простая стартовая точка |
| Ridge (L2 регуляризация) | 0.444 | 0.714 | 0.15 | Регуляризация не улучшила результат |
| Lasso (L1 регуляризация) | 0.445 | 0.715 | 0.15 | Регуляризация не улучшила результат |
| Random Forest (default) | 0.336 | 0.833 | 29.65 | Лучшая точность, но медленный инференс |
| Gradient Boosting (default) | 0.376 | 0.798 | 8.33 | Требует настройки параметров |
| **Gradient Boosting (tuned)** | **0.337** | **0.831** | **1.66** | **Оптимальный баланс** |

### 5.3. Выбор финальной модели

**Финальная модель:** Gradient Boosting (tuned)

**Параметры финальной модели:**
| Параметр | Значение |
|----------|----------|
| n_estimators | 100 |
| max_depth | 7 |
| learning_rate | 0.1 |

**Сравнительный анализ кандидатов:**

| Критерий | Gradient Boosting (tuned) | Random Forest | Linear Regression |
|----------|--------------------------|---------------|-------------------|
| MAE | **0.337** | 0.336 | 0.444 |
| R2 | **0.831** | 0.833 | 0.714 |
| Скорость инференса | **1.66 мс** | 29.65 мс | 8.24 мс |
| Интерпретируемость | Средняя | Высокая | Высокая |
| Сложность деплоя | Низкая | Низкая | Низкая |
| Объём модели | ~5 МБ | ~50 МБ | ~1 КБ |

**Обоснование выбора:**

1. **Точность:** Gradient Boosting (tuned) достиг MAE = 0.337, что всего на 0.001 хуже Random Forest, но при этом на порядок быстрее.
2. **Скорость:** Инференс 1.66 мс делает модель пригодной для реальных приложений с высокими требованиями к задержкам.
3. **Ресурсы:** Модель имеет небольшой объём (~5 МБ) и не требует GPU для работы.
4. **Интерпретируемость:** В отличие от нейросетей, градиентный бустинг позволяет получить важность признаков.

**Учтённые компромиссы (trade-offs):**

| Компромисс | Решение | Обоснование |
|------------|---------|-------------|
| Точность vs Скорость | Выбран Gradient Boosting | Random Forest точнее на 0.001, но медленнее в 18 раз |
| Простота vs Качество | Выбран ансамбль | Линейные модели слишком неточны (MAE=0.444 vs 0.337) |
| Интерпретируемость vs Точность | Принята средняя интерпретируемость | Feature importance достаточно для объяснения предсказаний |
| Extended тюнинг vs Базовый | Использован базовый GridSearch | Расширенный поиск не дал значительного улучшения |

**Итоговое заключение:**

Gradient Boosting (tuned) выбран в качестве финальной модели, так как она обеспечивает **оптимальный баланс** между:
- высокой точностью (MAE = 0.337, R2 = 0.831)
- высокой скоростью (инференс 1.66 мс)
- низкими ресурсными требованиями (~5 МБ, без GPU)
- достаточной интерпретируемостью (feature importance)

Модель готова к деплою в production-среду.

## 6. Архитектура решения и сервис

### 6.1. Архитектура пайплайна

```
[Входные данные JSON] → [FastAPI endpoint /predict] → [Pydantic валидация]
                                                              ↓
[Ответ JSON] ← [Gradient Boosting модель] ← [Загрузка модели из artifacts/]
```

**Компоненты:**
- **API слой:** FastAPI приложение ([`src/happiness/api.py`](api.py)) — обрабатывает HTTP-запросы
- **Валидация:** Pydantic модели ([`src/happiness/schemas.py`](schemas.py)) — проверяет входные данные
- **Модельный слой:** ([`src/happiness/predict.py`](predict.py)) — загружает модель и выполняет предсказание
- **Артефакты:** `artifacts/` — хранит сериализованную модель и метаданные

### 6.2. API и endpoints

| Endpoint | Метод | Описание | Коды ответа |
|----------|-------|----------|-------------|
| `/health` | GET | Проверка работоспособности сервиса | 200 |
| `/predict` | POST | Предсказание индекса счастья | 200, 422, 500 |
| `/docs` | GET | Swagger UI документация | 200 |

**Пример запроса к `/predict`:**
```json
{
  "Log_GDP_per_capita": 9.5,
  "Social_support": 0.8,
  "Healthy_life_expectancy_at_birth": 65.0,
  "Freedom_to_make_life_choices": 0.7,
  "Generosity": 0.1,
  "Perceptions_of_corruption": 0.7,
  "Positive_affect": 0.6,
  "Negative_affect": 0.3
}
```

**Пример ответа:**
```json
{
  "life_ladder": 5.202
}
```

### 8.1. Ограничения проекта

| Ограничение | Описание |
|-------------|----------|
| **Данные** | Пропуски в признаках (2-5%) были удалены, что могло привести к потере информации |
| **Модели** | Не проводился тюнинг для Random Forest |

| **Нейросетевые подходы** | Не рассматривались из-за ограниченного времени |
| **Масштабируемость** | Сервис рассчитан на однопоточную обработку запросов |
